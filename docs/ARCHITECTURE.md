# 《魔塔世界》架构与编码规范指南 (Architecture & Conventions)

本文档定义《魔塔世界》(Tower of Sorcery) 前端系统的分层架构、数据流向、交互规范与核心设计铁律。

设计范围（用户于2026-10-06明确）：只做桌面端，当前布局验收1280×900、1440×1000；手机不在开发设计范围内。历史响应式分支与手机验证记录不构成当前要求，后续不新增手机设计。保留既有SVG、粗粝锻铁/羊皮纸主题；普通边框与锁定入口降低强调，金色主要用于可执行行动。锁定入口继续通过 `getFeatureAccess()` 解释任务及领奖条件，不修改准入规则；报价、耐久、资源成熟信息必须与现有生产层一致。

---

## 1. 系统总体架构 (System Architecture)

### 法师终战反制与中期装备目标（2026-10-24）

剧情100层两次有限龙息在命中后抽走勇者当前魔力60%；只有实际拥有且仍有魔力的魔力护盾会过载，按实抽魔力3倍追加原始魔法伤害。该部分在暴击计算后加入，仍经过铁卫、减伤、魔抗及剩余魔力护盾，法力吸收按实际受伤回蓝；无魔力护盾只抽魔力。两次阶段的原阈值、蓄势、命中下限、余烬和基础属性保留，旧版终战不带新字段。

命中后另引导20秒黑焰逆流，普通生命回复降低90%，不叠加，不影响死亡预防和复活。`restorePlayerHealth()`统一光环、吸血、技能、魔药、伙伴、合击、符文和存活时圣遗物自愈；控制、敌方魔力耗尽、到期或战斗结束清除引导。它是首领引导，不是净化可免的附加异常，战前和战斗栏均说明边界。状态只存在本场，不写存档。培养后的魔能光环先取整再回蓝，避免小数魔力经护盾传入生命和战报。

每条战报携带当时的`playerMp/enemyMp`，战斗属性区随演播更新双方当前魔力，不能把开场满魔力显示成抽取后的余额。吟游诗人原有25速度移入`getPlayerActionSpeed()`，战斗内不再重复增加；实际战斗节奏保持，侧栏及换装预览补齐同一加成。

`settleCastleVictory()`负责调用`checkUnlockRelics(floor, false)`并返回`newRelics`，UI只展示觉醒结果。生产模拟、网页和刷新不能获得不同圣遗物战力。旧档按最高层补齐的既有迁移仍保留，不撤销已得资产。

中期三段支线保留原ID、等级、3胜目标、装备选择与奖励。每胜派生一段`storyBeats`，由结算写入系统日志、任务簿显示，不另存剧情游标。`getOptionalEquipmentGoal()`只提供旁路入口，不替换主线。`getCommissionEquipment()`共用领奖装备构造，`getCommissionEquipmentPreview()`用真实有效属性层只读比较当前装备和未强化奖励，含出手间隔；不开随机数、不生成UID、不扣资源。

### 终战范围龙息与有限余烬（2026-10-24）

剧情100层的两段龙息增加`minHitChance: 85`：仅本次施法采用普通命中与85%的较高值，仍允许闪避，不改变普攻、时空禁锢、其他首领或旧版终战。成功命中后，每阶段留下`echoes.charges = 2`次余烬。随后每次勇者个人行动结束最多结算一次，消耗龙皇100魔力，造成勇者最大生命2%的魔法伤害，不暴击、不因连击/追击段数重复。首次施法有原阶段预警，余烬另行预警；两个阶段合计最多四次。

余烬由本场`pendingPhaseEchoes`队列维护，不增加敌方行动、不改独立进度。勇者行动后若龙皇正受眩晕/混乱，或魔力不足，清除剩余队列；击败龙皇或勇者死亡后不再结算。每次已消费的次数不会因复活重置。伤害经过与直接受击共用的`mitigatePlayerDamage()`，包含铁卫18%庇护、装备减伤、魔抗和魔力护盾；假死、古堡复活继续有效。套装法力吸收按减免后实际伤害回复且不超过缺失魔力，致死后不先行回蓝。净化只免附带异常，不移除余烬。战报使用`phaseEcho/sourceAbilityName`，避免当作一次新的敌方施法统计。

战前`getBossTactics()`及战斗技能栏直接读取命中下限、次数、比例和反制说明；挑战/领奖固定操作区保留。全部状态只存在本场演算，不写入五槽、伙伴、技能或装备。精确机制为合理单机改编，原版未确认。初版10%与必中方案已因实际战士回归失败撤回，最终保留普通输出通路，不提高龙皇基础属性。

### 终战阶段、王座重试与中期装备支线（2026-10-24）

- `towerLevels.js → towerView.js → combat.js`：剧情100层保留生命400000、攻击6200、防御2600、速度110与开场护盾60000。生命70%/35%各蓄势一次，下一次敌方独立行动施法；分别额外造成勇者生命上限22%/28%的魔法伤害，百分部分不暴击，仍经过佣兵减免、减伤、魔抗与魔力护盾。控制中断消耗本阶段尝试，破魔可耗尽后续施法资源；状态免疫只免除附带异常。尝试集合仅存在于本场演算，不增加存档字段。
- `battleView`敌方技能栏按`hpThreshold`选择阶段说明，普通周期法术继续显示行动间隔；不能把有限龙息显示为每两次行动反复施放。战前反制说明和战斗栏均从实际配置读取。
- `journey.canRetryFinale → state.startFinaleRetry → towerView/main`：仅新版剧情、80级、已交付25章、已通99层或停在100层、未首通且已结清探险可重返王座。创建新探险身份并从100层开始，不补每日次数、不耗钥匙、不恢复前层收益。胜负继续走原结算、消费和首通幂等路径；旧探险回调无效，首通后入口关闭。重试不免除战斗体力、魔药和耐久消费。
- `commissions.js → recordCommissionEvent → claimCommission(id, choiceId)`：25/40/60级家书、星图、灯火三段顺序支线，各需目标区域普通讨伐3胜，前置须已交付。装备提供进攻/守护二选一，职业适配共用 `specializeEquipment`，真实写入背包并可预览/穿戴。领奖先标记选择，再一次发布完整经验、货币与物品；取消/非法选择无消费，重复拒绝。UI选择仅在视图内保存，`commissions[id].choiceId`只随已领取奖励落盘。
- 旧档无新支线时不补历史胜利或奖励；原有任务簿/装备/五槽保留。备份校验选择合法性和状态一致性；损坏的已领取记录保守保持已领取，避免迁移成为重复奖励来源。上述精确机制和剧情均为合理单机改编，来源边界见还原审计。

### 桌面启动与战败生命周期（2026-10-24）

`start_game.bat → start_game.py`固定以项目目录运行HTTP服务，优先复用8088上具有游戏模块入口的可用首页。无服务时使用当前Python隐藏启动`server.py`，追加`output/server.log`并等待最多15秒，再打开默认浏览器；其他服务占用端口时直接报错，不杀进程。启动器不读写浏览器资料或存档，默认浏览器使用玩家自己的存储；CLI可见/无头测试继续独立context。`--no-browser`只用于启动就绪检查。

`battleView`必须在`close()`清空`currentCombat`之前读取战败建议。随后注销回调、关闭界面、记录战报、调用原结算并在`finally`完成战斗消费。重复确认不重复结算；致命败退和300秒超时都须走完古堡折半经验、体力/魔药/耐久消费及保存。此次修复不新增保存字段、不改变战斗数值；超时建议明确输出准备方向。

### 启动恢复与首领反制收尾（2026-10-24）

`index.html` 在模块入口之前注册捕获阶段的资源错误监听与8秒启动看门狗。入口或依赖加载失败、长时间未完成初始化时，羊皮纸提示提供手动重新载入；不自动重试、不读写存档。`main.init()` 最后调用 `completeGameStartup()`，迟到成功也移除提示并恢复可见操作焦点。已复现模块断连时document完成但无app/state/创角的静默空壳；尚不能证明此前偶发超时一定由此引起。故障注入、正常启动和业务pageerror分开计数。

剧情版100层保持生命400000、攻击6200、防御2600、速度110，增加60000开场护盾，“时空禁锢”每3次敌方独立行动施放，提前一次蓄势。旧版任务序列保留原终战参数。`combat.js` 的独立护盾不触发古门狂暴/献祭；普通攻击、技能和既有破盾合击均有效，不要求拥有指定伙伴。龙之门/时空之门关底分别新增可预警、可打断的重创/减速法术，保留基础属性、奖励、300秒上限和既有免疫/疲劳规则。

数据链为 `towerLevels/dungeons → towerView战斗参数 → battleView → runCombat`。古堡传`openingShield`，古门传`abilities/mp/maxMp`，不能只在配置模拟或战前说明中生效。`bossTactics.js` 只从实际敌方配置生成折叠反制说明，详情独立滚动、挑战按钮固定。精确护盾/间隔/法术均为合理单机改编，不新增原作公式断言。

无新增存档字段；旧等级、装备、培养、阵容、体力、五槽和已领取账本不重算奖励、不重置。已有剧情存档以后挑战采用新机制，旧版终战仍按旧版配置；古门新技能适用于以后挑战，不追溯已结算战斗。

### 新手操作与成长续修（2026-10-24）

- 新档教学顺序由`getQuestList(data)`按`onboardingVersion`决定，不重排旧档任务。上下任务导航统一经`getJourneyGuidance()`解析缺装、加点等准备步骤；行囊穿戴只重绘本页、恢复有效选择和焦点。筛选/排序由`selectBagItems()`只读派生，材料用途导航共用`getBagItemDestination()`。
- `getCompanionTrainingQuote()`从拥有关系、等级、经验、体力与英雄等级计算营地训练报价；`trainCompanion()`复核报价和真实资产，一次扣金币/魔晶/1份兽肉，经正常伙伴经验曲线升级，拒绝过期或疲劳请求。无单独保存的训练余额，不补发免费伙伴经验。新档第13章交付后开放；满体力喂养在UI和状态层共同拒绝。
- `getInvestigationSteps()`及`getInvestigationEarnedExperience()`统一有限调查预算。古门成功结算记录最高`floorProgress`并递增`expGranted`，重入早层不加经验，最后一层完成目标；交付只补未发经验并发其他原报酬。旧未领奖/部分记录保留未付预算，备份检查进度与预算一致，不把新字段缺失解释成已经支付。
- `SYNERGY_FORMATIONS → getPlayerSynergyStrike()`只从有效主宠与佣兵确定高级合击；基础伙伴保留职业合击。技能说明与战斗共用同一效果配置，破盾扣实际余盾，控制/减防只作用仍存活目标。精确配对是单机改编。
- 猎人自动成长当前为每级攻击4.5、速度1.25，下文5.5/1.5是历史记录；10秒基础间隔和敏捷四项收益保持。旧档只重算有效属性，不撤回等级/潜能/装备/宠物资产。版本间平衡证据使用冻结同一角色和配对战斗随机数，不能用不同掉落路线耗时推断因果。

本次没有改变五槽、职业锁定、探险身份、奖励幂等和备份校验。准备充分的终战样本仍偏容易，未用全体敌人数值加成掩盖，也未将“可通关”等同于“难度已完成调定”。间歇初始化超时仍列已知未定位问题，额外冷启动通过不能作为已修复证据。

### 一次性任务簿（2026-10-24）

`config/commissions.js`维护具名支线、国家指引、酒馆委托的目标/对白/奖励及进度校验。状态独立于主线`questProgress`和每日`tavern.bounties`，只保存`commissions[id] = { status: active|ready|claimed, current }`。`settleWildVictory()`、`settleWildBossVictory()`与有探险身份防重的`settleCastleVictory()`在成功结算后调用`recordCommissionEvent()`；失败、导航、接取前历史和钥匙跳层不推进。单次普通胜利可同时满足两份适配目标，不额外重复结算战斗收益。

`claimCommission()`先写claimed，再通过`addExp(..., false)`/`gainCurrency(..., false)`/`grantBattleLoot()`发放全部报酬，最后一次notify，避免升级通知保存一半奖励。满袋不丢失委托报酬，同ID堆叠；暗金蛋带正常egg类型，继续现有45级准入及拥有关系。徽记是任务证据而非可售背包物，交付标记留存，不引入丢弃后无法交付问题。

旧档缺字段迁移为空任务簿，不补历史胜利、不补奖；partial/ready/claimed都可刷新和跨日保存。备份拒绝未知任务/非法进度/状态矛盾，直接读档对损坏claimed保守保留已领取，避免重复发奖。王宫/酒馆各有独立可滚动任务页，原生按钮、等级禁用、目标导航与交付后的焦点恢复共用原羊皮纸弹窗。国家指引按存档归属生成背景，所有国家共用同一个任务ID，不形成可换国刷三份奖励。

规则证据与改编边界见`RESTORATION_AUDIT.md`：已确认名称/等级/奖励方向；NPC、对白、森林/魔塔目标、数量及45级孵化折中均属合理单机改编。

### 还原复核补充（2026-10-24）

条目级证据及后续任务缺口见 [RESTORATION_AUDIT.md](RESTORATION_AUDIT.md)。凤凰改为30%复活/20%最大生命，小妖精改为每次致命攻击50%免除、持续伤害不适用；概率来自同期攻略。凤凰每场一次尝试、假死涵盖反击而不涵盖混乱自伤，保留为有明确边界的单机方案，不宣称原作隐藏限制已核实。`tryFeignDeath()` 共用普通/技能直伤与敌方反击入口，不改变独立行动进度或300秒超时；凤凰恢复向下取整至少1点。特性由配置解析，不保存战斗次数，不需要改写旧宠物或迁移五槽。

新档开场采用运营介绍可确认的沉睡亚诺人、灾变千年后魔塔重现背景，后接现有罗兰/巡逻队单机任务。首次对话开窗前聚焦实际任务入口，避免取消后返回隐藏创角控件。已核实世界史不等于已找到原版任务目标与对白。

### 主副宠、职业培养与行动节奏（2026-10-24，已实施）

实施结果与验证范围统一读取 `PROJECT_STATE.md` 文首交接。规则依据与改编参数分开维护，不把能通关或截图相似当作原作隐藏公式的证据。

- **自动成长与终战备战续修（2026-10-24）**：猎人每级自动攻击7.5→5.5、速度2.5→1.5，10秒基础节奏与下述敏捷系数保留。降低自动获得的复合收益，保留投入敏捷的价值；精确成长仍属合理单机改编，旧档只重算有效属性，等级、潜能、装备、神兽与五槽资产不变。不要把职业最快本身当作缺陷或追求三职业等速。扩大随机路线后发现泰坦/狂暴魔药在装备、封号、主宠之前乘倍率，导致高等级角色远低于描述的35%生命/25%护甲/35%攻击；现移到完整属性汇总后、取整之前，侧栏、战斗和换装预览共用。原有草药成本、三战期限、同配方替换与保存结构保留，旧有效魔药不补发、不扣次。主线终战98–100层仅在现有魔药无法覆盖余下层数且材料足够时提示去炼金，无材料不阻断。炼金按钮按草药、魔晶和永久潜能上限原生禁用，成功后先重绘再打开弹窗，关闭/取消时能恢复有效控件焦点。主线导航至角斗必须显式选择对决子页，避免上次商行选择遮住NPC入口。

套装机制：仅耐久大于0的装备计入2/4件共鸣；破损符文之语也失效。技能等级每级提高主动技能倍率、被动与光环数值5%，不改变蓝耗、概率、段数；统一由 `getClassSkills()` 提供，套装说明同步为职业技能等级。命中、暴击、闪避采用百分点，原配置的100/150数值改为10%/15%，避免概率直接封顶。破击值为扣除目标防御的固定值；智慧女神伤害作用于法师法术或具有破击的主动攻击；胜利女神斩杀在目标生命不高于30%时生效。法力吸收取实际承受的生命伤害且不超过魔力上限；命运女神连击只触发于普攻，追加攻击遵守首领护盾。以上均为重制机制，未证明为原版公式。

战斗命中：敌方默认命中95，显式0保留；双方命中率公式保持原有50%下限/99%上限，玩家闪避实际参与敌方命中判定。魔塔每场一次免费复活按既有说明恢复生命和魔力全满，不改变非魔塔复活规则。

伤害与回血：直接攻击的生命伤害不超过目标剩余生命，盾吸收单独记录；吸血、生命汲取、法力吸收和反射取实际生命伤害，不可把溢出伤害或盾吸收转化为回复。

神兽特性：体力低于60时天赋与学习魔典全部失效；连击30%、银龙再生2.5%、凤凰复活50%等由 `traitEffect` 驱动。鸟妖虚弱持续目标3次行动，重击刷新不叠乘；重创本场只施加一次；疾风提高先手速度，冷静提供控制概率；翼蛇女将有限减益时长乘1.5向上取整，不延长永久减速。梦魇将实际吸血加倍、毒伤乘4。腐蚀毒刺魔典在声望商店300声望兑换，命中后毒伤为实际生命伤害15%、持续2回合，重击刷新不叠加，可与梦魇/翼蛇女搭配，仍占4个魔典槽之一。新孵化按图鉴等级准入筛选；已拥有旧档神兽保留。上述组合与概率统一为当前重制规则，非原版考据结论。

铁匠资源：声望商店保留购买接口ID `crystal_protect`，发放材料ID统一为 `protect_crystal`；旧档材料ID转换保留数量/UID。保护水晶仅在强化失败时消耗，成功不扣，8星仍为上限。满背包可向既有材料堆栈购买或摘回宝石；无空间建立新堆栈时不扣货币、不摘除原宝石。镶嵌位置必须是合法整数，拒绝NaN/小数等输入后才扣金币/宝石。开孔沿用每件4孔上限，物品说明同步。

首领施法：`towerLevels.abilities` 是当前重制的结构化规则，20层毒风飞龙/30层骨龙/剧情100层龙皇分别每3/4/3次敌方个人行动施放剧毒风暴/死灵龙息/时空禁锢，提前一次行动蓄势；旧版100层间隔仍为5。施法替代该次普攻，不额外追加攻击；眩晕/混乱可打断蓄势，魔力不足不能施放。魔抗最多减免60%对应法术伤害；受击施加的状态按实际生命伤害确定毒伤，净化免疫所有状态、圣洁免疫虚弱/减速/重创、清醒免疫控制、庇护降低持续伤害80%。净化魔典在声望商店300兑换，仍占用一个既有魔典槽。警告、伤害、免疫和到期恢复均使用既有战报。

首领重生与汲取（2026-10-05已验收）：50层 `rebirth` 配置25%生命，`checkEnemyRebirth()` 在行动与毒伤后检查单次重生，活跃纳迦 `antiRevive` 封断，体力低于60失效；不初始化新战斗、不重置护盾/阶段/首通记录。60层每4回合蓄势后消耗60魔力施放1.1倍法术，`enemyLifesteal` 回复50%实际生命伤害，银飞马 `lifestealResist` 将回复减半；护盾吸收/溢出伤害不计入，回复最多到满生命，满血不写虚假回复事件。生产测试区分开场天赋说明与真实封断事件，不将说明计为重复触发。六条浏览器路径和自然角色200配对种子验证范围见PROJECT_STATE，不能视为自然获取神兽或全塔通关。

背包出售：`getEquipmentSaleQuote()`/`sellEquipment()` 仅接受行囊中的一件闲置装备，UID必须唯一；宝石/符文未摘除或记录异常时拒售，材料不自动出售。确认时校验报价，移除装备后才支付金币，重复请求无法再次支付。回收价取显式物品价格的一半；无价格按等级×30×品质倍率的一半，最少1金币；这是重制定价。旧装备无UID时补稳定身份并保存，保留现有UID。既有物品操作区显示报价和出售确认，强化星级在确认中说明；不新增布局或视觉系统。

换装预览：`getEquipmentPreview(uid)` 与 `equipItem()` 共用 `getEquippableItem()` 的物品/部位/等级/职业校验；`getEffectiveStats(equipped = this.data.equipped)` 接收只读候选穿戴表，完整复用强化、耐久、镶嵌、重铸及套装计算，不临时修改角色状态、不通知或保存。行囊出手间隔使用战斗 `getActionInterval()`，并另列当前/目标符文之语描述，避免静态面板遗漏触发效果。

行囊扩容：`bagCapacity` 每档独立持久化，40→60→80→100→120；`getBagCapacity()` 统一主动交易/摘宝石/显示容量，战利品与卸装继续保留。四档游戏币成本10000/20000/30000/40000金币和50/100/150/200魔晶，属于重制定价。`expandBag(expectedCapacity)` 先检查当前报价身份/两种资源再一起扣费并扩容，过期确认/不足/上限均不变。旧本地数据非法容量归40，备份导入非法容量拒绝；不根据背包物品数量赠送扩容。声望和军勋发货成功后才扣货币，满袋已有材料堆叠仍可交易。

铁匠分解：`getEquipmentDisassemblyQuote()`/`disassembleEquipment(slot, expectedUid)` 验证唯一装备身份、品质与镶嵌记录，先无损摘除宝石/符文才允许分解。弹窗捕获部位与UID，确认时换装不会拆错物品；重复确认不重复发料。白/蓝/黄金保留3枚黄金晶石，暗金/紫金3枚暗金晶石，是当前重制规则；星级随装备销毁，确认说明。产物走保留奖励的 `grantBattleLoot()`，满袋不丢失，与已有材料堆叠；UI只调用生产方法，不直接修改穿戴/材料。

重制续章：`quests.js` 21~26章由配置 `milestone` 定义要塞/指定古门/70层/七晋升/时空古门/100层。`isQuestMilestoneAchieved()` 读取生产战绩，`reconcileQuestMilestones()` 在领奖、读档及相关胜利后认可已有成就，仅当前任务可领且领取先锁定。新高层首领要求 `claimedBossRewards`，不从最大抵达层推断；老存档缺账本需实际重胜相应首领。旧 `completed` 且20章已领、26章未领时接首个未领续章；新终章不重新打开。现有任务导航定位边境/对应古门/晋升/魔塔。六章合计77万金币及探索补给，为重制剧情与数值，不宣称原版还原。

地下城探索：`startDungeonExpedition()` 消耗一次每日五次配额，当前探索必须完成/撤离才能再次入场；`expeditionId` 是持久化并发/幂等身份，不能作为可忽略的行政记录。胜利/撤离显式匹配当前身份与门/楼层，旧回调即使同门同楼层也不能结算新探索。`settleDungeonVictory()` 先推进/结束探索，再按既有公式发EXP/金币/魔晶及终战120声望、装备/暗金晶石x2；材料堆叠，战利品满袋保留，新装备需求等级为古门准入等级。终战清除活动身份并记录通关，任务从此记录认可。旧活动存档补稳定身份。UI只负责战斗参数、显示和调用生产者；撤离/失败调用已有静音接口，不启用音效。

## 2. 目录分层与职责 (Directory Responsibilities)

### 2.1 `js/config/` (静态配置与数值表 — 17 个模块)
- **定位**：纯数据字典，禁止编写含有副作用（如操作 DOM 或修改全局状态）的代码。
- **代表模块**：
  - `classes.js`：三大基础职业与城邦国徽配置。
  - `items.js`：十部位装备、13 套远古套装羁绊与属性、消耗品、宝石与魔晶。
  - `pets.js` / `petSkills.js`：22 种西方魔幻原著神兽宠物属性、天资上下限与专属技能表。
  - `trials.js`：王宫圣王大殿七阶晋升配置（20~80 级）、等级/声望准入与属性加成表。
  - `towerLevels.js`：魔塔 1~100 层守卫配置与守关领主链。
  - `dungeons.js`：地下城七大古门（试炼、勇气、变幻、死亡、风暴、巨龙、时空）多层深度探险配置、中间层守卫生成器 `getDungeonFloorGuard`、三阶段关底史诗领主参数（P1 神圣护盾、P2 绝境狂暴、P3 契约自愈）、四大全屏合击奥义 `SYNERGY_STRIKES` 与关底套装散件掉落池 `generateDungeonDrop`。
  - `maps.js`：5 大野外地图怪物与准入等级数值表。
  - `runes.js`：8 大西方高魔符文石与 7 大远古符文之语配方。
  - `relics.js`：6 大远古神圣圣遗物属性与触发机制。
  - `factionWar.js`：三大阵营边境要塞争夺战与帝国军衔配置。
  - `tavern.js`：王都皇家酒馆、悬赏通缉榜与佣兵公会配置。
  - 其他：`arena.js`（竞技场）、`dragonSlaying.js`（屠龙）、`estate.js`（领地庄园）、`quests.js`（主线任务链）、`slaves.js`（战俘役使）。

### 2.2 `js/core/` (核心逻辑与状态引擎)
- **定位**：游戏运转的核心状态机、算法引擎与持久化管线。
- **代表模块**：
  - `state.js`：全游戏唯一状态管理中枢 `gameState`，驱动玩家潜能、背包、穿戴、宠物出战、转职等级计算等，内置事件发布/订阅分发机制实现逻辑与视图解耦。
  - `combat.js`：高魔回合制战斗引擎，负责暴击、闪避、韧性、技能触发、神兽协同攻击的离散演算，以及首领 P1 远古神圣护盾吸收、P2 绝境狂暴 (+35% 攻)、P3 冥府死契随从献祭自愈与佣兵神兽全屏合击奥义结算。
  - `storage.js`：本地 localStorage 5 大独立存档位管理，保障数据隔离与向下兼容迁移。
  - `sound.js`：静音音频抽象层（杜绝 Web Audio 报错与外部音频依赖）。

### 2.3 `js/assets/` (矢量图标与美术资产注册)
- **定位**：全局矢量 SVG 图标与美术资产的注册表与渲染中枢。
- **代表模块**：
  - `icons.js`：职业立绘、装备与神兽的精美矢量 SVG 插画资产库。
  - `vectorIcons.js` (`getVectorIcon`)：132 个矢量 SVG 贴图资产与图标注册表及统一检索方法。
  - `images.js`：图片资源路径映射与加载辅助。

### 2.4 `js/effects/` (视觉特效层)
- **定位**：游戏界面视觉氛围与粒子特效。
- **代表模块**：
  - `atmosphere.js`：复古暗黑魔幻氛围粒子与光效渲染。

### 2.5 `js/ui/` (视图表现与交互层)
- **定位**：负责 DOM 渲染、子页面状态流转与用户点击事件响应。
- **代表模块**：
  - `main.js`：游戏全局控制器 `GameApp`（位于 `js/main.js` 根目录），负责顶栏刷新、导航切换与子视图挂载。
  - `modal.js` (`gameModal`)：拟真羊皮纸质感弹窗系统，替代原生 `alert()` 与 `confirm()`。
  - `iconHelper.js` (`renderGameIcon`)：矢量 SVG 图标统一渲染方法。
  - `townView.js`：王都主城（含铁匠铺、转职大殿、竞技场、屠龙、钓鱼等全屏子路由）。
  - `estateView.js`：领地庄园（含炼金、灵脉矿产、佣兵役使等子路由）。
  - `heroView.js`：勇者属性面板（内含 `EquipView` 装备穿戴子视图）。
  - `battleView.js`：回合制战斗全屏演出视图。
  - `systemLogView.js`：常驻系统日志流与动态过滤。
  - `bagView.js` / `petView.js` / `towerView.js` / `wildView.js`。
  - `charSelectModal.js`：初次创角职业选择弹窗。
  - `archiveModal.js`：5 槽位存档管理弹窗。
  - `questTracker.js`：常驻任务追踪与自动寻路。
  - `tooltip.js`：装备与道具信息浮层。

### 3.2 绘画素材与功能图标规范 (Zero Unicode Emoji)
- 页面与提示中严禁写入类似 `⚔️`, `🛡️`, `💰`, `🧙‍♂️` 等 Emoji 字符。
- 2026-10-29 用户明确要求装备、道具使用真实绘画贴图，覆盖历史“100% SVG”约束。`itemArtworkCatalog.js` 保存图集坐标；`itemArtwork.js` 优先解析物品 ID，再解析旧图标路径/部位，`renderGameIcon()` 统一输出 PNG 图集切片。保留旧配置和存档路径，不改变物品字段、数值或业务。
- 用户同日补充要求头像及常用界面徽记也采用绘画。`js/assets/paintedIcons.js` 提供三职业/三佣兵头像、16界面徽记与旧路径别名，供统一渲染和兼容 `getVectorIcon()` 使用；已经渲染的位图包装也可供旧战斗调用继续传递。装备、材料、头像、徽记不得用SVG栅格化冒充绘画。未映射符号仍保留兼容资源，不宣称全库无SVG。
- 调用示例：
  ```javascript
  // 正确示例

  container.innerHTML = `${swordIcon} <span>光明裁决圣剑</span>`;
  ```

### 3.5 视觉美术风格铁律与《魔域》复古西幻规范 (Visual Art Direction Specification)
本规范为后续所有游戏美术、立绘、装备与场景资产的开发红线，任何 AI 或设计师必须严格遵循：

《魔域》与《暗黑破坏神 II》是本项目选择的美术参考，不代表已核实的《魔塔世界》原版画风。现阶段保留下述美术约束；更换整体方向须由用户决策。

#### 1. 核心画风基调：2006 经典《魔域》(Eudemons Online) 暗黑粗粝复古风
- **整体氛围**：纯正西方暗黑高魔题材，古老、沧桑、粗粝、厚重，带有强烈的魔化与征战杀伐气息（参考《魔域》、《暗黑破坏神 II》、《奇迹MU》经典年代质感）。
- **两严禁（红线）**：
  1. **严禁“现代精致/二次元糖水风”**：杜绝圆润光滑塑料感、杜绝大眼日漫萌妹脸庞、杜绝花哨轻浮的现代手游卡牌高光与金色花边；
  2. **严禁“写实摄影/实拍风 (Photorealistic)”**：杜绝真实世界相机质感，必须保持复古 2.5D 手绘魔幻游戏 Sprite 质感。

#### 2. 材质与表现特征
| 资产类型 | 必须体现的特征 | 严禁出现的特征 |
|---|---|---|
| **金属刀剑与重铠** | 粗粝锻造黑铁、斑驳暗沉古铜、战损划痕与缺口、暗红血痕、暗黑哥特阴影。 | 锃亮镜面抛光、塑料光滑质感、现代数码无瑕渐变。 |
| **法杖法袍与魔法** | 扭曲干枯古木、恶魔/野兽角骨、深渊幽冥紫雾、幽绿毒瘴、暗沉死灵魔光。 | 艳丽霓虹粉蓝光斑、现代科技光效、糖果色光芒。 |
| **神兽幻兽与魔物** | 凶猛威严古兽体态、风化硬质鳞甲、獠牙尖爪、原始野性、深邃冷峻眼神。 | 宠物小精灵式萌系大眼、圆润可爱宠物造型、日漫美少女。 |
| **场景画卷与建筑** | 饱经风霜的古老中世纪黑石古堡、破败斑驳石柱、阴郁苍凉天幕、魔雾沉降。 | 现代高饱和度童话梦幻小镇、崭新平整石板路。 |

#### 3. 工业级通用生图咒语公式 (Prompt Formula)
所有资产生成必须以该结构为标准模板：
```text
Classic 2006 vintage dark fantasy MMORPG game icon/portrait, Eudemons Online art style, Diablo 2 retro 2.5D gritty hand-painted aesthetic.
[主体描述: 材质、战损、古老特征、粗粝细节],
[魔法与暗黑特效: 幽冥魔化光、血色暗芒、腐蚀烟雾、厚重阴影],
antique weathered relic, rough hand-painted texture, dark gothic shadows, centered composition,
isolated on solid plain dark background, zero text, no modern frame --ar 1:1
```

**强制负向提示词 (Mandatory Negative Prompts)**：
`photorealistic, photo, 3D render, smooth plastic, modern mobile game, clean cute cartoon, anime princess, kawaii, glossy slick digital art, vector sticker, overly refined, pristine, bright colorful candy lighting, clean glowing gold borders`

#### 4. 后续批量开发与入库流水线 (Future Asset Pipeline)
1. **统一尺寸**：
   - 装备/道具图标：1:1 比例（1024x1024 原图生成，入库自动适应 64x64 / 128x128 游戏容器）；
   - 神兽/领主立绘：1:1 圆形/方形徽章 或 3:4 战斗全身立绘；
   - 场景与主城画卷：16:9 全景画卷。
2. **自动化入库**：图片保存至项目 `downloads/` 目录并规范命名（如 `items__wpn_sword.png`），执行 `python3 organize_images.py` 即可全自动分拣归位入库，通过 `js/ui/iconHelper.js` 统一呈现。
