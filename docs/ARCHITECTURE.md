# 《魔塔世界》架构与编码规范指南 (Architecture & Conventions)

本文档定义《魔塔世界》(Tower of Sorcery) 前端系统的分层架构、数据流向、交互规范与核心设计铁律。

---

## 1. 系统总体架构 (System Architecture)

本项目采用轻量、高效的纯原生 ES6+ 前端模块化架构，无需任何重型前端构建框架（如 React/Vue/Webpack），在现代浏览器中直接以 `<script type="module">` 与 ES 模块 import 组织运行。

当前为浏览器单机项目：JavaScript 负责游戏规则，localStorage 保存五个独立槽位，`server.py` 仅提供静态 HTTP 文件服务。尚无账号、多人同步或服务端经济系统。

设定依据：2010 年运营介绍中的亚诺大陆与萨格尔、克斯特、亚丁三城，以及当年职业资料中的力量战士、敏捷猎人、智力法师，与现有基础配置对应。具体技能数值、晋升和装备规则仍须逐项核实。参考：[37 游戏介绍](https://www.37.com/news/2010/0105/1859.html)、[新浪职业介绍](https://games.sina.com.cn/w/n/2010-03-11/1527381313.shtml)。符文之语、六大圣遗物、佣兵合击与边境要塞等暂列原版归属待核实；不以缺少来源直接判定为原创或删除。

装备槽位以 `ITEM_SLOTS` 为准，保持十槽。按用户确认，任务与地下城勇气塔盾奖励改为同套装勇气精钢护手，属性与品质保持不变；旧存档自动转换，护手位已占用时转入背包，保留既有装备。此兼容规则属于本次重制决策，不作为原版考据结论。

数值与机制续作规则：普通野外奖励由地图配置和 `GameState.settleWildVictory()` 统一结算，每10胜保证一份兽肉；晋升属性逐阶累积；任务里程碑认可已有高层通关、封号与紫金神兽，领奖仍幂等。剧情遭遇由状态层推进与读档恢复，不依赖特定弹窗。普通怪经验调整与连续讨伐补给属于单机重制参数，未证实为原版数值；巡逻收益保持原值。

探索经济：新角色没有免费佣兵，已有契约保留。野外首领奖励遵循地图魔晶与装备品质配置；游吟诗人只对野外、魔塔、地下城战胜收益应用金币+40%、魔晶+1，不影响任务与军饷。魔塔首领首通物品和魔晶即时入账，经验与金币保留撤离领取/败退折损规则；领取记录由存档 `castle.claimedBossRewards` 保证，重刷按普通层公式结算，不再补发首通物品。旧档不追扣收益、不依据最高层推断已经领取，升级后首次胜利开始记录。100层本次探险只能结算一次，须撤离后再次入塔。30/100层护盾奖励改为既有护手槽。重铸只接受有效装备与黄金/暗金晶石，指定材料不足时不自动改用其他材料。

四维数值约定：力量每点攻击+2.6；智力每点攻击+2（法师+2.6）、魔力+8；敏捷每点速度+1.3、暴击+0.22%、闪避+0.16%，猎人额外攻击+2.6；体魄每点生命+16、防御+1.5。符文、重铸和圣遗物遵循相同贡献，全四维按四项分别计算。当前系数为单机重制规则。主线新增秘宝追踪的叙事衔接同样属于本次补写，不作为原版剧情证据。

套装机制：仅耐久大于0的装备计入2/4件共鸣；破损符文之语也失效。技能等级每级提高主动技能倍率、被动与光环数值5%，不改变蓝耗、概率、段数；统一由 `getClassSkills()` 提供，套装说明同步为职业技能等级。命中、暴击、闪避采用百分点，原配置的100/150数值改为10%/15%，避免概率直接封顶。破击值为扣除目标防御的固定值；智慧女神伤害作用于法师法术或具有破击的主动攻击；胜利女神斩杀在目标生命不高于30%时生效。法力吸收取实际承受的生命伤害且不超过魔力上限；命运女神连击只触发于普攻，追加攻击遵守首领护盾。以上均为重制机制，未证明为原版公式。

战斗命中：敌方默认命中95，显式0保留；双方命中率公式保持原有50%下限/99%上限，玩家闪避实际参与敌方命中判定。魔塔每场一次免费复活按既有说明恢复生命和魔力全满，不改变非魔塔复活规则。

伤害与回血：直接攻击的生命伤害不超过目标剩余生命，盾吸收单独记录；吸血、生命汲取、法力吸收和反射取实际生命伤害，不可把溢出伤害或盾吸收转化为回复。

神兽特性：体力低于60时天赋与学习魔典全部失效；连击30%、银龙再生2.5%、凤凰复活50%等由 `traitEffect` 驱动。鸟妖虚弱持续目标3次行动，重击刷新不叠乘；重创本场只施加一次；疾风提高先手速度，冷静提供控制概率；翼蛇女将有限减益时长乘1.5向上取整，不延长永久减速。梦魇将实际吸血加倍、毒伤乘4。腐蚀毒刺魔典在声望商店300声望兑换，命中后毒伤为实际生命伤害15%、持续2回合，重击刷新不叠加，可与梦魇/翼蛇女搭配，仍占4个魔典槽之一。新孵化按图鉴等级准入筛选；已拥有旧档神兽保留。上述组合与概率统一为当前重制规则，非原版考据结论。

铁匠资源：声望商店保留购买接口ID `crystal_protect`，发放材料ID统一为 `protect_crystal`；旧档材料ID转换保留数量/UID。保护水晶仅在强化失败时消耗，成功不扣，8星仍为上限。满背包可向既有材料堆栈购买或摘回宝石；无空间建立新堆栈时不扣货币、不摘除原宝石。镶嵌位置必须是合法整数，拒绝NaN/小数等输入后才扣金币/宝石。开孔沿用每件4孔上限，物品说明同步。

首领施法：`towerLevels.abilities` 是当前重制的结构化规则，20层毒风飞龙/30层骨龙/100层龙皇分别每3/4/5回合准备剧毒风暴/死灵龙息/时空禁锢，下次实际行动施放，替代该次普攻，不额外追加攻击；眩晕/混乱可打断蓄势，魔力不足不能施放。魔抗最多减免60%对应法术伤害；受击施加的状态按实际生命伤害确定毒伤，净化免疫所有状态、圣洁免疫虚弱/减速/重创、清醒免疫控制、庇护降低持续伤害80%。净化魔典在声望商店300兑换，仍占用一个既有魔典槽。警告、伤害、免疫和到期恢复均使用既有战报，不新增操作界面。

首领重生与汲取（2026-10-05已验收）：50层 `rebirth` 配置25%生命，`checkEnemyRebirth()` 在行动与毒伤后检查单次重生，活跃纳迦 `antiRevive` 封断，体力低于60失效；不初始化新战斗、不重置护盾/阶段/首通记录。60层每4回合蓄势后消耗60魔力施放1.1倍法术，`enemyLifesteal` 回复50%实际生命伤害，银飞马 `lifestealResist` 将回复减半；护盾吸收/溢出伤害不计入，回复最多到满生命，满血不写虚假回复事件。生产测试区分开场天赋说明与真实封断事件，不将说明计为重复触发。六条浏览器路径和自然角色200配对种子验证范围见PROJECT_STATE，不能视为自然获取神兽或全塔通关。

背包出售：`getEquipmentSaleQuote()`/`sellEquipment()` 仅接受行囊中的一件闲置装备，UID必须唯一；宝石/符文未摘除或记录异常时拒售，材料不自动出售。确认时校验报价，移除装备后才支付金币，重复请求无法再次支付。回收价取显式物品价格的一半；无价格按等级×30×品质倍率的一半，最少1金币；这是重制定价。旧装备无UID时补稳定身份并保存，保留现有UID。既有物品操作区显示报价和出售确认，强化星级在确认中说明；不新增布局或视觉系统。

行囊扩容：`bagCapacity` 每档独立持久化，40→60→80→100→120；`getBagCapacity()` 统一主动交易/摘宝石/显示容量，战利品与卸装继续保留。四档游戏币成本10000/20000/30000/40000金币和50/100/150/200魔晶，属于重制定价。`expandBag(expectedCapacity)` 先检查当前报价身份/两种资源再一起扣费并扩容，过期确认/不足/上限均不变。旧本地数据非法容量归40，备份导入非法容量拒绝；不根据背包物品数量赠送扩容。声望和军勋发货成功后才扣货币，满袋已有材料堆叠仍可交易。

铁匠分解：`getEquipmentDisassemblyQuote()`/`disassembleEquipment(slot, expectedUid)` 验证唯一装备身份、品质与镶嵌记录，先无损摘除宝石/符文才允许分解。弹窗捕获部位与UID，确认时换装不会拆错物品；重复确认不重复发料。白/蓝/黄金保留3枚黄金晶石，暗金/紫金3枚暗金晶石，是当前重制规则；星级随装备销毁，确认说明。产物走保留奖励的 `grantBattleLoot()`，满袋不丢失，与已有材料堆叠；UI只调用生产方法，不直接修改穿戴/材料。

重制续章：`quests.js` 21~26章由配置 `milestone` 定义要塞/指定古门/70层/七晋升/时空古门/100层。`isQuestMilestoneAchieved()` 读取生产战绩，`reconcileQuestMilestones()` 在领奖、读档及相关胜利后认可已有成就，仅当前任务可领且领取先锁定。新高层首领要求 `claimedBossRewards`，不从最大抵达层推断；老存档缺账本需实际重胜相应首领。旧 `completed` 且20章已领、26章未领时接首个未领续章；新终章不重新打开。现有任务导航定位边境/对应古门/晋升/魔塔。六章合计77万金币及探索补给，为重制剧情与数值，不宣称原版还原。

地下城探索：`startDungeonExpedition()` 消耗一次每日五次配额，当前探索必须完成/撤离才能再次入场；`expeditionId` 是持久化并发/幂等身份，不能作为可忽略的行政记录。胜利/撤离显式匹配当前身份与门/楼层，旧回调即使同门同楼层也不能结算新探索。`settleDungeonVictory()` 先推进/结束探索，再按既有公式发EXP/金币/魔晶及终战120声望、装备/暗金晶石x2；材料堆叠，战利品满袋保留，新装备需求等级为古门准入等级。终战清除活动身份并记录通关，任务从此记录认可。旧活动存档补稳定身份。UI只负责战斗参数、显示和调用生产者；撤离/失败调用已有静音接口，不启用音效。

阵营军衔：`factionWar.totalMerit` 为累计获得战功，`merit` 为可兑换余额；兑换只扣余额，胜利累计加两者、按累计晋衔，军衔特质与军饷保持既得等级。`getTotalFactionMerit()` 用有效累计、余额、已有军衔门槛中的最大值提供安全下界；旧档无法恢复全部历史消费，不赠送消费余额。加载持久化此下界，非法累计类型/负数/小数的备份拒绝。现有军需横幅展示两种数值，无新增布局。

## 2. 目录分层与职责 (Directory Responsibilities)

### 2.1 `js/config/` (静态配置与数值表 — 17 个模块)
- **定位**：纯数据字典，禁止编写含有副作用（如操作 DOM 或修改全局状态）的代码。
- **代表模块**：
  - `classes.js`：三大基础职业与城邦国徽配置。
  - `items.js`：十部位装备、13 套远古套装羁绊与属性、消耗品、宝石与魔晶。
  - `pets.js` / `petSkills.js`：22 种西方魔幻原著神兽宠物属性、天资上下限与专属技能表。
  - `trials.js`：王宫圣王大殿七阶晋升配置（20~80 级）、等级/声望准入与属性加成表。
  - `towerLevels.js`：魔塔 1~100 层守卫配置与守关领主链。
  - `dungeons.js`：地下城七大古门（试炼、勇气、变幻、死亡、风暴、巨龙、时空）多层深度探险配置、中间层守卫生成器 `getDungeonFloorGuard`、三阶段关底史诗领主参数（P1 神圣护盾、P2 绝境狂暴、P3 契约自愈）、四大全屏合击奥义 `SYNERGY_STRIKES` 与关底套装散件掉落池 `generateDungeonDrop`。
  - `maps.js`：5 大野外地图怪物与准入等级数值表。
  - `runes.js`：8 大西方高魔符文石与 7 大远古符文之语配方。
  - `relics.js`：6 大远古神圣圣遗物属性与触发机制。
  - `factionWar.js`：三大阵营边境要塞争夺战与帝国军衔配置。
  - `tavern.js`：王都皇家酒馆、悬赏通缉榜与佣兵公会配置。
  - 其他：`arena.js`（竞技场）、`dragonSlaying.js`（屠龙）、`estate.js`（领地庄园）、`quests.js`（主线任务链）、`slaves.js`（战俘役使）。

### 2.2 `js/core/` (核心逻辑与状态引擎)
- **定位**：游戏运转的核心状态机、算法引擎与持久化管线。
- **代表模块**：
  - `state.js`：全游戏唯一状态管理中枢 `gameState`，驱动玩家潜能、背包、穿戴、宠物出战、转职等级计算等，内置事件发布/订阅分发机制实现逻辑与视图解耦。
  - `combat.js`：高魔回合制战斗引擎，负责暴击、闪避、韧性、技能触发、神兽协同攻击的离散演算，以及首领 P1 远古神圣护盾吸收、P2 绝境狂暴 (+35% 攻)、P3 冥府死契随从献祭自愈与佣兵神兽全屏合击奥义结算。
  - `storage.js`：本地 localStorage 5 大独立存档位管理，保障数据隔离与向下兼容迁移。
  - `sound.js`：静音音频抽象层（杜绝 Web Audio 报错与外部音频依赖）。

### 2.3 `js/assets/` (矢量图标与美术资产注册)
- **定位**：全局矢量 SVG 图标与美术资产的注册表与渲染中枢。
- **代表模块**：
  - `icons.js`：职业立绘、装备与神兽的精美矢量 SVG 插画资产库。
  - `vectorIcons.js` (`getVectorIcon`)：132 个矢量 SVG 贴图资产与图标注册表及统一检索方法。
  - `images.js`：图片资源路径映射与加载辅助。

### 2.4 `js/effects/` (视觉特效层)
- **定位**：游戏界面视觉氛围与粒子特效。
- **代表模块**：
  - `atmosphere.js`：复古暗黑魔幻氛围粒子与光效渲染。

### 2.5 `js/ui/` (视图表现与交互层)
- **定位**：负责 DOM 渲染、子页面状态流转与用户点击事件响应。
- **代表模块**：
  - `main.js`：游戏全局控制器 `GameApp`（位于 `js/main.js` 根目录），负责顶栏刷新、导航切换与子视图挂载。
  - `modal.js` (`gameModal`)：拟真羊皮纸质感弹窗系统，替代原生 `alert()` 与 `confirm()`。
  - `iconHelper.js` (`renderGameIcon`)：矢量 SVG 图标统一渲染方法。
  - `townView.js`：王都主城（含铁匠铺、转职大殿、竞技场、屠龙、钓鱼等全屏子路由）。
  - `estateView.js`：领地庄园（含炼金、灵脉矿产、佣兵役使等子路由）。
  - `heroView.js`：勇者属性面板（内含 `EquipView` 装备穿戴子视图）。

## 3. 核心设计规范与铁律 (Conventions & Invariants)

### 3.1 纯正西方魔幻用词规范 (Western High Fantasy Lexicon)
项目严格贯彻中世纪西方高魔题材，所有新代码、新道具、UI 文案严禁出现中式修真/仙侠/武侠词汇：

| 严禁使用的中式词汇 | 必须采用的西方魔幻词汇 | 说明 |
|---|---|---|
| 气血 / 真气 / 内力 | **生命 / 魔力 / 战力** | 基础属性统一为 HP / MP / Power |
| 秘籍 / 功法 / 心法 | **魔导书 / 技能卷轴 / 古典教义** | 技能与学习道具 |
| 飞贼 / 刺客神偷 | **暗影女盗 / 游侠 / 斥候** | 盗贼系野外奇遇或敌人 |
| 乾坤 / 混元 / 阴阳 | **远古 / 神圣 / 混沌 / 虚空** | 高阶转职与神技修饰 |
| 丹药 / 洗髓丹 | **药剂 / 天资魔晶 / 潜能秘药** | 消耗品与属性提升品 |
| 太古 / 洪荒 | **远古 / 创世 / 上古** | 历史背景与神装定名 |

### 3.2 100% 矢量 SVG 图标规范 (Zero Unicode Emoji)
- 页面与提示中严禁写入类似 `⚔️`, `🛡️`, `💰`, `🧙‍♂️` 等 Emoji 字符。
- 必须使用 `renderGameIcon(iconName, size, extraClass)` 输出洁净矢量 SVG：
  ```javascript
  // 正确示例
  const swordIcon = renderGameIcon('sword', 18, 'text-gold');
  container.innerHTML = `${swordIcon} <span>光明裁决圣剑</span>`;
  ```

### 3.3 拟真羊皮纸弹窗规范 (gameModal Only)
- 杜绝一切 `alert(...)` 或 `confirm(...)` 调用。
- 必须统一通过 `gameModal` 触发：
  ```javascript
  // 提示信息
  gameModal.alert("圣水已枯竭，请前往药剂店补充！", "王室谕令");

  // 确认操作
  gameModal.confirm("确定要消耗 500 金币重铸这把圣剑吗？", "铁匠铺协议", () => {
      // 执行重铸
  });
  ```

### 3.4 创角与职业锁定规范
- 存档职业选定在初次进入时通过 `charSelectModal.js` 确立，并写入 `gameState.hasChosenClass = true`。
- 一旦锁定，页面中不得提供任何切换职业的入口。
- 刷新或读取存档时，如果 `hasChosenClass === true`，绝不重复弹出创角界面。

### 3.5 视觉美术风格铁律与《魔域》复古西幻规范 (Visual Art Direction Specification)
本规范为后续所有游戏美术、立绘、装备与场景资产的开发红线，任何 AI 或设计师必须严格遵循：

《魔域》与《暗黑破坏神 II》是本项目选择的美术参考，不代表已核实的《魔塔世界》原版画风。现阶段保留下述美术约束；更换整体方向须由用户决策。

#### 1. 核心画风基调：2006 经典《魔域》(Eudemons Online) 暗黑粗粝复古风
- **整体氛围**：纯正西方暗黑高魔题材，古老、沧桑、粗粝、厚重，带有强烈的魔化与征战杀伐气息（参考《魔域》、《暗黑破坏神 II》、《奇迹MU》经典年代质感）。
- **两严禁（红线）**：
  1. **严禁“现代精致/二次元糖水风”**：杜绝圆润光滑塑料感、杜绝大眼日漫萌妹脸庞、杜绝花哨轻浮的现代手游卡牌高光与金色花边；
  2. **严禁“写实摄影/实拍风 (Photorealistic)”**：杜绝真实世界相机质感，必须保持复古 2.5D 手绘魔幻游戏 Sprite 质感。

#### 2. 材质与表现特征
| 资产类型 | 必须体现的特征 | 严禁出现的特征 |
|---|---|---|
| **金属刀剑与重铠** | 粗粝锻造黑铁、斑驳暗沉古铜、战损划痕与缺口、暗红血痕、暗黑哥特阴影。 | 锃亮镜面抛光、塑料光滑质感、现代数码无瑕渐变。 |
| **法杖法袍与魔法** | 扭曲干枯古木、恶魔/野兽角骨、深渊幽冥紫雾、幽绿毒瘴、暗沉死灵魔光。 | 艳丽霓虹粉蓝光斑、现代科技光效、糖果色光芒。 |
| **神兽幻兽与魔物** | 凶猛威严古兽体态、风化硬质鳞甲、獠牙尖爪、原始野性、深邃冷峻眼神。 | 宠物小精灵式萌系大眼、圆润可爱宠物造型、日漫美少女。 |
| **场景画卷与建筑** | 饱经风霜的古老中世纪黑石古堡、破败斑驳石柱、阴郁苍凉天幕、魔雾沉降。 | 现代高饱和度童话梦幻小镇、崭新平整石板路。 |

#### 3. 工业级通用生图咒语公式 (Prompt Formula)
所有资产生成必须以该结构为标准模板：
```text
Classic 2006 vintage dark fantasy MMORPG game icon/portrait, Eudemons Online art style, Diablo 2 retro 2.5D gritty hand-painted aesthetic.
[主体描述: 材质、战损、古老特征、粗粝细节],
[魔法与暗黑特效: 幽冥魔化光、血色暗芒、腐蚀烟雾、厚重阴影],
antique weathered relic, rough hand-painted texture, dark gothic shadows, centered composition,
isolated on solid plain dark background, zero text, no modern frame --ar 1:1
```

**强制负向提示词 (Mandatory Negative Prompts)**：
`photorealistic, photo, 3D render, smooth plastic, modern mobile game, clean cute cartoon, anime princess, kawaii, glossy slick digital art, vector sticker, overly refined, pristine, bright colorful candy lighting, clean glowing gold borders`

#### 4. 后续批量开发与入库流水线 (Future Asset Pipeline)
1. **统一尺寸**：
   - 装备/道具图标：1:1 比例（1024x1024 原图生成，入库自动适应 64x64 / 128x128 游戏容器）；
   - 神兽/领主立绘：1:1 圆形/方形徽章 或 3:4 战斗全身立绘；
   - 场景与主城画卷：16:9 全景画卷。
2. **自动化入库**：图片保存至项目 `downloads/` 目录并规范命名（如 `items__wpn_sword.png`），执行 `python3 organize_images.py` 即可全自动分拣归位入库，通过 `js/ui/iconHelper.js` 统一呈现。
